Token efficiency audit layer for production AI agents

The Core Insight

A workload-dependent share of agent tokens is structurally redundant — in our own audits of 24 public traces, step redundancy alone runs 36–41%. TraceRazor finds the waste and tells you exactly how to fix it.

TraceRazor reads a completed agent trace (JSON), scores it across thirteen efficiency metrics, and outputs a 0-100 Token Audit Score (TAS) with fix patches. No agent modification required. Everything runs offline.

Architecture

tracerazor-core

13 metrics, scoring engine, fix generation, reports. Zero network dependencies. This is where all analysis happens.

tracerazor-ingest

Parsers for raw JSON, LangSmith, and OpenTelemetry trace formats. Converts any format to the internal Trace struct.

tracerazor-semantic

Bag-of-words similarity backend. Optional LLM embeddings (OpenAI, Anthropic, or compatible) for enhanced mode.

tracerazor-store

SurrealDB persistence: traces, known-good-paths, baselines, and anomaly detection rolling windows.

tracerazor-server

Axum REST API + WebSocket live events + embedded React dashboard. Serves the full UI at port 8080.

tracerazor.runtime

Python event processor with provenance-aware usage, local disk spooling, privacy controls, spawned-agent linkage, and advisory streaming detectors.

tracerazor-cli

CLI entry point: audit, optimize, bench, simulate, compare, cost, export.

Python Integrations

The 1.1 platform wheel contains the native auditor, runtime event API, Agent Skill assets, MCP entry point, and optional adapters for LangGraph, CrewAI, and OpenAI Agents. Public 1.1 artifacts remain pending until the clean-machine release matrix passes.

Python Integrations

TraceRazor 1.1 uses one package and one provenance-aware runtime contract. Framework SDKs remain optional, and estimated usage is marked degraded rather than treated as enforcement-quality evidence.

Unified runtime

from tracerazor.runtime import configure
Emits tracerazor-event/v1, preserves token provenance, and stores local-redacted run artifacts.

Agent bootstrap

tracerazor agent install --host auto --scope project
Previewable, idempotent adapters for Codex, Claude Code, Gemini CLI, and a generic wrapper.

MCP

pip install "tracerazor[mcp]>=1.1,<2"
Local diagnosis, comparisons, policy checks, validation records, and evidence verification.

Framework callbacks

Optional OpenAI Agents, LangGraph, and CrewAI adapters feed the same runtime processor. Unsupported automatic registration is reported instead of silently claiming capture.

Multi-Agent Support

Parent and child runs carry linked W3C trace context, run receipts, and project policy. TAS remains ordinal: do not average or rank unrelated child agents. Use linkage, exact usage, tool-loop findings, and same-workload before/after comparisons for workflow-level decisions.

Quick Start

Option 1: Docker

git clone https://github.com/ZulfaqarHafez/tracerazor
cd tracerazor
docker compose up --build
# Requires TRACERAZOR_API_TOKEN in .env; trust the local Caddy CA first.
# Dashboard at https://localhost:8080

Option 2: Cargo

cargo build --release
./target/release/tracerazor audit trace.json

Option 3: Python

pip install "tracerazor[mcp]>=1.1,<2"

from tracerazor import Tracer

with Tracer(agent_name="my-agent") as t:
    t.reasoning("Analyzing request...", tokens=200)
    t.tool("search", params={}, output="result", success=True, tokens=150)

report = t.analyse()
print(report.summary())
# TAS 78.5/100 [GOOD] | 4 steps, 350 tokens | Estimated 90 tokens (26%)

CI/CD Gate

tracerazor compare baseline.json candidate.json --regression-threshold 10
# Exit code 1 on a declared same-workload regression
